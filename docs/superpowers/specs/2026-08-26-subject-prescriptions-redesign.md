# 六科对症学习处方与 0826 重设计规格

## 背景

`prompt/0826.md` 提出三个长期方向：吸收优秀白板笔记工具的能力、扩展英语单词/短语出题方式、让 AI 为数学题生成帮助理解条件的交互图。当前项目已经有六科学科筛选、错因分类和七种诊断板，但学科差异主要散落在页面条件分支和少量建议文本中，尚未形成可复用、可展示、可检验的“学科处方”。

## 本轮目标

先建立六科学科策略层，并在练习体验中直接呈现。它是后续英语题型矩阵、数学交互图和白板工作台的共同入口，不尝试在一个提交中同时完成三个大型子系统。

## 方案选择

### 方案 A：继续在页面里添加条件分支

改动快，但 `Practice.tsx` 会继续增长，学科文案、工具和证据规则容易漂移，Pages 与后端数据也难保持一致。

### 方案 B：建立声明式学科处方注册表（采用）

把六科的诊断重点、动作、证据、下一步、关键错因和工具映射集中为纯 TypeScript 数据与查询函数。首页、练习页、诊断总览和未来白板入口消费同一注册表；工具组件仍按学科独立实现。

### 方案 C：立即建设完整白板与 AI 交互图平台

最终能力最强，但会同时引入画布模型、AI 协议、来源采集和大量 UI 状态，无法在当前未提交工作存在时可靠验证，也不能先解决六科同质化。

## 架构

新增 `frontend/src/lib/subject-prescriptions.ts`，只负责稳定的学科策略数据和查询：

- `focus`：该科首要观察的认知对象；
- `actions`：学生现在能执行的 2 至 3 个动作；
- `evidence`：什么产物才算完成诊断；
- `nextStep`：完成后如何做迁移验证；
- `causeGuidance`：学科内关键错因的具体动作与诊断工具。

新增 `SubjectPrescriptionPanel`，用渐进披露展示当前学科处方。选择“全部”时展示六科紧凑卡片；选择单科时展示该科完整处方和可用工具。`Practice` 继续负责数据请求和错题操作，不再拥有处方文案。

既有 `SubjectEvidenceEditor` 保持学科组件隔离。首轮沿用语文得分点、数学推导、英语长难句、物理受力/运动、化学方程式和地理因果链；映射从硬编码 switch 逐步迁入策略层。未来数学 `geometry_scene` 和英语题型证据可作为新工具加入，不破坏当前协议。

## 数据流

1. 全局学科选择进入 `Practice`。
2. 页面通过 `prescriptionFor(subject)` 得到展示策略。
3. 错题通过 `guidanceFor(subject, cause)` 得到建议与工具标识。
4. 工具产出的版本化 evidence 继续经现有 API 或 Pages static adapter 保存。
5. 六科总览使用同一策略生成空状态与下一步，不把“暂无错题”误写成“没有学习方向”。

## UI 与理解负荷

- 标题先说明“这科先查什么”，再给动作，不先展示抽象统计。
- 当前动作最多三项，每项用动词开头。
- 证据和下一步默认收在同一卡片下，不另开多层导航。
- 六科总览使用紧凑卡，避免一次展开 24 条说明。
- 颜色仅辅助辨认；名称、文本和图标共同表达，不依赖颜色传意。

## Pages 与错误处理

- 注册表和面板完全前端化，不依赖后端。
- 静态演示至少提供六科错题/处方可见状态；已有 evidence 保存仍使用内存适配器。
- 未知学科回退到通用记录流程，不伪造某一科处方。
- 未知或新错因保留后端 taxonomy 的原始建议；只有注册表明确覆盖的组合才显示专属工具。

## 测试与验收

- 纯函数测试证明六科都有唯一的 focus、动作、证据与下一步，且无未知工具。
- 组件测试覆盖“全部”六卡、单科完整内容、键盘切换和未知学科回退。
- Practice 测试证明切换学科后处方与错因工具同步变化。
- static-demo 测试证明六科演示数据存在且不发起真实 `/api` 网络请求。
- 完成后运行前端 Vitest、TypeScript、lint、build；处理当前工作区已有 Go 改动后再跑完整 Go 测试。

## 后续边界

本轮不声称已完成 B 站字幕爬取、完整白板画布、英语所有题型生成器或任意数学题 AI 作图。它建立这些功能进入项目时必须遵循的学科策略和证据边界；后续按 `prompt/0826.md` 的四阶段验收继续小步实现。
